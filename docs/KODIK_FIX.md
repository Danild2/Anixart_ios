# Kodik после рекламы — 0.2.1

Пользователь сообщил о MediaError4 и видимой ошибке «данной страницы не существует» после рекламы на любых аниме/озвучках. Остальной интерфейс принят без изменений.

Исправление сохраняет публичный контекст iframe, который действительно загрузила официальная рекламная страница. После настоящего advertEnded открывается обычный iframe с тем же uid и адресом эпизода, без рекламных флагов only_a/advert_debug. Контекст берётся из WKNavigationAction, не задаётся константой. Параметры подписанного URL сохраняют исходное percent encoding. Обычный iframe загружается через официальный frontend: браузер формирует правильный Referer и сохраняет тот же контекст сайта. При отсутствии контекста показывается ошибка, адрес не придумывается.

Сообщения старого рекламного документа игнорируются во время перехода и после него. Для Kodik в режиме VLC обнаружение HTTP MP4/HLS адреса больше не требует успешного декодирования этого формата WebKit. MediaError4 при уже найденном адресе не блокирует VLC; приложение при этом не объявляет видео воспроизводящимся и не выдумывает duration/frames. HTML, blob и локальные URL не принимаются как внешний поток.

Проверка выпуска: все unit-тесты и один целевой iOS UI-сценарий Kodik через настоящий рекламный frontend до появления media URL. UI дополнительно проверяет отсутствие видимой ошибки несуществующей страницы и баннера playbackFailure. Полная проверка декодирования в VLC и другие источники не запускаются согласно ранее указанному пользователем ограничению.

Профиль, четыре вкладки Liquid Glass, обложки, Libria и Bundle ID local.anixartport.client не менялись. Версия пакета 0.2.1. Итоговый результат и контрольная сумма заносятся в RELEASE.json после завершения CI.
